# Telegram · группа Нурлана и администратора

## Что добавлено

- Новая заявка: магазин, представитель, дата поставки, товары и кг, номер документа.
- Акт переработки / выпуска: сотрудник, товар, фактические кг, дата. Это запись выпуска на проверку, а не уже проведённое списание или начисление.
- При настроенном HTTPS-адресе кнопка открывает конкретную заявку или акт в приложении. При локальном запуске без публичного адреса отправляется текст без кнопки. Вход и права приложения сохраняются.
- Напоминания в 09:00 и 17:00 по `Asia/Qyzylorda`, только если есть заявки `submitted` или акты `draft`. Время настраивается.
- Настройки → «Telegram · группа цеха»: статус, ошибки, очередь, проверочное сообщение, повтор после исправления доступа.

## Включение

1. В Telegram открыть https://t.me/BotFather, отправить `/newbot`, задать имя и уникальный username, получить токен.
2. Создать группу с Нурланом и администратором, добавить бота. Разрешить ему отправлять сообщения. Доступ администратора Telegram боту не требуется. Privacy mode можно оставить включённым.
3. На рабочем сервере записать `TELEGRAM_BOT_TOKEN` в `back-main/back-main/.env` (при Docker — в `deploy/.env`). Не добавлять токен во фронтенд, Git или публичное демо.
4. В группе отправить `/start@username_бота`. Из каталога backend выполнить `node scripts/telegram-setup.cjs`. Команда покажет найденные группы и их ID, не выводя токен. Она не подтверждает updates и не меняет webhook. При существующем webhook использовать отдельного бота.
5. Указать `TELEGRAM_GROUP_ID=-100...` (использовать фактический ID, обычные группы могут иметь другой отрицательный формат), `TELEGRAM_ENABLED=true`, `TELEGRAM_REMINDER_HOURS=9,17`. При запуске без Docker также указать `TELEGRAM_APP_URL=https://адрес-приложения`.
6. Перезапустить backend. В Docker Compose эти параметры уже передаются сервису backend; HTTPS-адрес берётся из `SITE_DOMAIN`.
7. Администратором открыть Настройки → Telegram → «Отправить проверку в группу». Проверить фактическое получение сообщения и открытие кнопки на телефоне.

Бот @CONDNurzhanBot подключён к группе COND; тестовое сообщение доставлено. Токен хранится только в серверных секретах. По явному разрешению владельца также включается публичное демо через TELEGRAM_ALLOW_PUBLIC_DEMO=true; каждое сообщение помечается «Демо COND». Без этого флага публичное демо блокирует отправку, облачная копия блокирует всегда. Старые документы не рассылаются задним числом.

## Как работает доставка

Очередь `telegram_messages` записывается в той же транзакции, что и новая заявка/акт. При откате нет уведомления. Повтор мобильной операции использует существующий механизм идемпотентности. Telegram не участвует в проведении склада или зарплаты.

На постоянно работающем Node-сервере обработчик запускается автоматически и проверяет очередь каждые 30 секунд. При отключённом интернете данные остаются в PostgreSQL. Телефон без интернета сначала отправляет документ на сервер после восстановления связи; Telegram получает уведомление затем. Работающий сервер и интернет необходимы для доставки.

Повторная доставка использует задержку 30 секунд–1 час и `retry_after` Telegram. После 8 неудач либо ошибки доступа уведомление видно в ошибках; администратор может повторить после исправления. Параллельные обработчики используют блокировку строк. Уже согласованные/отменённые заявки и обработанные акты до отправки пропускаются. Напоминание отправляется максимум один раз за выбранный час; пропущенные старые напоминания не догоняются.

Telegram `sendMessage` не предоставляет ключ идемпотентности: в редком случае, когда Telegram принял сообщение, но ответ потерялся или сервер упал до фиксации, повтор может дать дубль. Текст содержит номер документа для распознавания. Ошибки не выводят URL с токеном.

Это интеграция постоянно работающего backend. В Vercel-демо очередь обрабатывается после ответа API через waitUntil и двумя защищёнными Vercel Cron Jobs. Утренний запуск — 04:00 UTC (09:00 Казахстан), вечерний — 12:00 UTC (17:00 Казахстан). CRON_SECRET проверяется на сервере. На Hobby фактический запуск возможен в течение выбранного часа. Если нет входящих запросов, повтор после сбоя Telegram произойдёт при следующем обращении или запуске cron; обещания фоновой проверки каждые 30 секунд для Vercel нет. На постоянно работающем Node-сервере интервал 30 секунд сохраняется.

## Проверка

`node scripts/test-telegram.cjs` создаёт и удаляет отдельную БД `cond_telegram_test_*`. Telegram заменён тестовым транспортом, реальные сообщения не отправляются. Проверяются транзакционный откат, повтор мобильной записи, параллельная доставка, сетевые ошибки, 429/403, часы Казахстана, отсутствие пустых напоминаний, права и блокировка публичного демо.

Официальная документация: https://core.telegram.org/bots/api#sendmessage и https://core.telegram.org/bots/features#botfather .
