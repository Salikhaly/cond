# Телефон, локальная работа и сервер

## Без интернета, Wi-Fi и доступного сервера

После первого входа приложение загружает интерфейс, справочники и последние данные на устройство. При следующем открытии без связи оно использует эту сохранённую копию.

Можно записывать приходы по уже заведённым материалам, выработку, заявки, выплаты и расходы. Администратор может рассчитать выпуск по сохранённой рецептуре и сохранить запрос на его проведение. Очередь находится в IndexedDB на этом телефоне, отдельно для аккаунта; она сохраняется после перезагрузки приложения. При связи приложение отправляет записи автоматически, пока оно открыто; есть кнопка ручной отправки. Для автоматической отправки после закрытия приложения Background Sync не реализован: откройте приложение при появлении связи.

Каждая запись помечена «На телефоне · ждёт отправки». Серверные остатки и зарплаты не меняются до подтверждения. Офлайн-расчёт предварительный: другой сотрудник может уже израсходовать сырьё или зарезервировать товар. При отправке сервер повторно проверяет права, материалы, остатки и суммы. Отклонённая запись остаётся видна с причиной и останавливает очередь до исправления/удаления отклонённой записи. Создание новых справочников и пользователей требует связи.

Каждая операция имеет уникальный номер. Результат обработки номера сохраняется в той же транзакции PostgreSQL, что и приход, списание или зарплата. Обрыв после выполнения и повторная отправка возвращают прежний результат, без повторного начисления. Для офлайн-выработки временный номер телефона сопоставляется с серверным перед отправкой проведения.

Не очищайте данные браузера и не удаляйте приложение до отправки очереди. Выход из аккаунта блокируется, пока есть неотправленные записи. Это не заменяет резервное копирование рабочей базы.

## Как открыть на телефоне сейчас

1. Запустить `PHONE.cmd` на этом компьютере. Он покажет адреса. Для текущей Wi-Fi сети адрес был `http://192.168.8.202:9000`; после смены сети он может измениться.
2. Подключить телефон к той же Wi-Fi сети и открыть адрес. Если Windows блокирует доступ, разрешить Node.js только для частной сети. Брандмауэр автоматически не изменялся.
3. Демо-аккаунты: `admin@local.test`, `worker@local.test`, `firm@local.test`, пароль `Local2026!demo`. Это тестовые данные и тестовые доступы.

Обычный HTTP-адрес компьютера в Wi-Fi позволяет проверить интерфейс и работу с сервером. Для установки PWA и надёжного повторного открытия приложения на телефоне без связи нужен доверенный HTTPS-адрес. Исключение `localhost` относится только к самому устройству: адрес `127.0.0.1` телефона не ведёт на ноутбук. Локальная проверка офлайн-загрузки выполнена в браузере компьютера на loopback-адресе. Реальные Android и iPhone ещё не проверены.

## Завтрашнее размещение на сервере

Это тот же проект: React + Node.js API + PostgreSQL. Обычный рабочий сервер принимает все операции и не требует режима облачной копии (`SYNC_ROLE=local`, либо не задавать). Он должен работать постоянно и иметь HTTPS. Собранный интерфейс обслуживает `front-main/front-main/scripts/local-web.js`, API запускает `node src/index.js`. Веб-процесс: WEB_HOST, WEB_PORT, API_PORT. API: HOST, PORT, параметры DB_*, SECRET_KEY, CLIENT_URL, SMTP. На рабочем сервере и при сборке клиента LOCAL_DEMO=false, NODE_ENV=production. Вход с кодом требует настроенного SMTP. База, резервные копии, HTTPS, перезапуск служб и реальные учётные записи на внешнем сервере ещё не настроены. Не публикуйте демонстрационные доступы и PostgreSQL.

## Дополнительная внешняя копия

Кроме очереди телефона реализована отдельная односторонняя отправка с основного сервера на сервер для просмотра. На основном: SYNC_CLOUD_URL=https://адрес, SYNC_SHARED_KEY=случайный общий секрет минимум 32 символа. На принимающем: SYNC_ROLE=cloud и тот же секрет. Копия доступна только для просмотра, привязка аккаунтов по email и роли; пароли и токены не передаются. Пользователей на принимающем сервере заводят отдельно. Это не вторая независимая база для записи и не полная резервная копия с паролями. Для полноценного переноса сохраняют всю PostgreSQL-базу.

Сейчас внешние адрес и секрет не заданы. Отправки в интернет нет. Проверка приёма, повторов, отказа связи и восстановления выполнена между двумя изолированными локальными базами.

Очередь привязана к адресу приложения и браузеру. Перед переходом с локального адреса на новый домен сначала отправьте все записи со старого адреса. Нельзя считать HTTP-предпросмотр по Wi-Fi установкой будущего HTTPS-приложения.
