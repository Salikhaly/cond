# Обмен и возврат — реализовано 28.10.2026

## Согласованные правила

- Представитель подаёт запрос по своей отгруженной накладной. Администратор подтверждает фактический приём, состояние товара и расчёт.
- Для каждого товара: вернуть в продажу, сначала проверить, списать. Проверяемый и списанный товар не увеличивает свободный остаток. После проверки можно распределять количество частями.
- Расчёт: вернуть деньги, уменьшить долг, зачесть следующую поставку. Допускается разделить сумму между несколькими подтверждёнными расчётами.
- Приём товара и финансовая часть независимы. Пожелание клиента в запросе не выдаёт деньги автоматически.
- В обмене администратор согласовывает цены замены. Приём возврата и отгрузка замены выполняются одной транзакцией: нехватка товара откатывает всё. Создаётся новая связанная накладная.

## Как пользоваться

Представитель: «Обмен / Возврат → + Возврат / Обмен». Выбрать магазин и отгруженную накладную, количество, клиента, причину и желаемый расчёт. Также можно открыть возврат прямо из карточки отгруженной заявки — накладная уже выбрана.

Администратор: «Обзор → Проверить возвраты» либо «Ещё → Обмен / Возврат» на телефоне. Открыть запрос, выбрать решение по товару, подтвердить фактическое получение и проверить проведение. После приёма запись появляется среди принятых.

Если товар на проверке: «Завершить проверку» → количество → в продажу / списать → причина → подтвердить. Обработать можно часть количества.

Финансы: «Оформить расчёт» → вид → сумма → подтверждение / основание → проверить → подтвердить. Наличные/перевод отмечаются только после фактической передачи денег, запись создаёт расход «Возврат покупателю».

Зачёт: сначала подтвердить сумму как зачёт следующей поставки, затем «Применить зачёт» и выбрать отгруженную накладную после возврата либо связанную накладную обмена. Для общего баланса сети можно выбрать другую точку той же сети; для раздельного учёта — только тот же магазин. Зачёт не создаёт второго движения денег.

История доступна в карточке: автор, время, действие, причина, принятые решения и суммы. Сервер сохраняет исходную запись и снимки событий. Акт возврата можно открыть для печати / PDF.

## Склад и деньги

Исходные продажи не переписываются. Проведённые возвраты проецируются в отчёт отдельными отрицательными строками на дату приёма. В сводке есть продажи до возвратов, возвраты и продажи после возвратов. Отражаются покупатели, товары, магазины и история товара. Физический возврат на склад отражается отдельно от уменьшения продаж: товар на проверке не считается приходом в продажу.

Расход возврата денег учитывается отдельно от уменьшения продаж. Не нужно повторно вычитать деньги из продаж после возвратов. Нельзя представлять эту разницу как чистую прибыль: полный учёт себестоимости отгрузок и покупательских оплат ещё не завершён. График продаж показывает отрицательные даты красным, диаграммы долей используют положительные итоги.

Уменьшение долга — подтверждённая корректировка конкретного возврата. Полный общий долг клиента неизвестен без начальных долгов и всех оплат; интерфейс это сообщает. Автоматической интеграции с банком нет: приложение записывает подтверждённую выдачу денег.

Зарплата кондитера при возврате не пересчитывается. Возврат относится к конкретной отгрузке нового модуля; для старых продаж без связанной отгруженной заявки требуется отдельно восстановить связь с исходной накладной.

## Защита от ошибок

- Количество всех проведённых возвратов не может превысить исходную отгрузку, в том числе при одновременных запросах.
- Частичные возвраты учитывают округление исходной суммы, полная сумма не может быть возвращена дважды за счёт дробления килограммов.
- Распределение товара после проверки не может превысить принятое количество.
- Расчёты не могут превысить сумму возврата, зачёт не может расходоваться дважды. Есть ограничения по клиенту, магазину, дате и сумме накладной.
- Каждая подтверждаемая операция получает сохраняемый на телефоне ключ идемпотентности. Повторная отправка после потерянного ответа не создаёт второй расход или движение склада.
- Непроведённый запрос можно отменить / отклонить с причиной, запись остаётся в истории. После проведения прямое редактирование и удаление не предусмотрены.
- Товар нельзя архивировать, пока по нему есть запрос возврата/обмена либо неразобранный остаток на проверке.
- Работник производства не получает данные возвратов или расчётов покупателей. Права проверяются на сервере.

## Офлайн

Представитель может создать запрос без сервера и Wi-Fi по уже загруженным накладным. Запрос сохраняется в очереди телефона и отправляется при связи; это ещё не проведённый возврат. Приём, списание и финансовые подтверждения выполняются с подключением к серверу. Существующие документы и история доступны из последнего загруженного снимка.

Исправлен выбор кэша: офлайн-навигация берёт index/страницы из текущей версии приложения. Предыдущий кэш используется только как запас для файлов уже открытых старых вкладок.

## Миграция и публикация

Добавлены таблицы goods_returns, return_dispositions, return_settlements, return_credit_uses, return_events. Старые строки продаж, зарплат и остатков не переписываются. Локальный запуск создаёт таблицы через существующую синхронизацию схемы. Публичное демо проверяет маркер schema:returns:v1 и создаёт новые таблицы под блокировкой PostgreSQL, сохраняя готовые демоданные. Возвраты входят в выгрузку и облачный снимок с проверкой прав.

Публичное демо использует текущую дату Казахстана для отчётов: возвраты, оформленные сегодня, не скрываются за фиксированной датой первоначального наполнения.

## Проверка

- 113 интеграционных проверок, включая возврат на проверку, годный товар, брак, три вида расчёта, повторные нажатия, конкурирующие запросы, дробные количества, ограничение зачётов по магазину, целостность обмена и сохранение зарплаты.
- 12 проверок облачного снимка / прав в изолированных базах.
- 23 проверки аналитики возвратов; дополнительно 81 существующая проверка планирования, отчётов и диаграмм (включая отрицательные полосы).
- Браузер 390 px: представитель создал запрос при выключенных API и web. После подключения на сервере была одна запись. После исправления кэша холодная офлайн-перезагрузка сохранила актуальный раздел и историю.
- Администратор принял 2 кг на проверку, подтвердил кредит 4000 ₸, вернул 1 кг в продажу. На проверке осталось 1 кг, свободный остаток стал 5 кг, расход денег не создан, сверка журналов прошла. Тестовая БД удалена после проверки.

## Удобство на телефоне · 28.10.2026

Возврат оформляется за три коротких шага: выбрать накладную карточкой с поиском, указать количество кнопками «− / + / Всё», отправить запрос. Частые причины выбираются одним нажатием. Перед отправкой видны магазин, товары и сумма. Черновик и режим обмена сохраняются на устройстве.

В списке сразу видны магазин, сумма, товар и следующий шаг. Подробности накладной и история раскрываются по запросу. Фильтры «Новые», «Проверить товар», «Расчёты» ведут к требующим внимания документам; доступный зачёт остаётся виден в расчётах. Администратор выбирает судьбу товара крупными кнопками; денежное подтверждение остаётся отдельным.

Проверено на экране 390 px в изолированной базе: представитель отправил 1 кг на 2000 ₸, администратор принял на проверку. Свободный остаток сохранился 6 кг, начисленная зарплата — 1500 ₸; продажи после возврата — 6000 ₸. Рабочая база для проверки не использовалась.
