# Проверка COND — 22 октября 2026

## Результат и границы

Проверены основные сценарии нового рабочего места и их связи с исходным кодом: ингредиенты, приходы, калькуляция, производство, зарплата, авансы, склад, заявки, отгрузки, продажи и расходы. 37 интеграционных проверок проходят в изолированной временной PostgreSQL-базе. Проверка текущей локальной базы через `/api/operations/reconciliation` не обнаружила расхождений после демонстрационного выпуска, отгрузки и нового прихода.

Это проверка предоставленного кода и локальных тестовых данных. Реальная историческая база клиента не предоставлена, поэтому сверка его фактических остатков, долгов и старых документов не выполнена. Заявлять полную эквивалентность всем прежним сценариям нельзя: предыдущий интерфейс оставлен для просмотра истории, запись идёт через новый учёт. Настоящая 1С, отправка писем через SMTP, печать на физическом принтере, Docker-сборка и работа на реальном iPhone/Android в этой проверке не проверялись.

## Найденные и исправленные расхождения

| Область | Что исправлено |
|---|---|
| Отчёты сотрудников | Проведённый выпуск отражается в исходных `Report` и `ReportProducts` с фактической датой, кг и сохранённой оплатой. |
| Зарплата | Начисление попадает в прежний месячный `Salary`. Новый раздел учитывает уже существующие начисления и авансы из этой же базы. |
| Выплаты | Записываются `Payment`, исходный `Advance`, выплаченная сумма в `Salary` и расход. Погашаются старые начисления перед новыми. |
| Продажи | Отгрузка записывает исходный `Income`: вес коробки, количество коробок (включая дробную часть), общий вес и сумму. Ранее количество всегда записывалось как 1. |
| Остатки | Новый склад хранит кг и резерв. Прежний `Product.weightTotal` отражает тот же вес, `quantity` — количество полных коробок. Остаток неполной коробки не теряется в кг. |
| Дробные количества | Физические количества расширены до 4 знаков после запятой явным обновлением типов; `sync({alter:true})` не применяется. Зарплата, выплаты и строки продаж округляются до тиынов. |
| Калькуляция | Цена за кг в прежней карточке обновляется при сохранении рецептуры и проведении выпуска. Проведённый выпуск сохраняет свой снимок. |
| Приход | Один документ может содержать несколько материалов. Ошибка в одной строке отменяет весь приход. Повтор номера у того же поставщика отклоняется. |
| Оплата закупки | Оплаченный приход создаёт расход; неоплаченный можно оплатить позже. Оплата не приходует сырьё повторно. Поставщик сохраняется в исходном справочнике контрагентов. |
| Другие расходы | Добавлены в новый раздел «Финансы», продолжают храниться в прежних `Outcome` и `OutcomeCategory`. |
| История | Связи с прежними журналами отмечаются отдельными идентификаторами. Повторный запуск не дублирует отчёты и авансы. Неоднозначные связи продаж не угадываются: сверка показывает проблему для разбора. |
| Доступ | Представителю недоступны чужие заявки, рецептуры и зарплаты; работник не может записать выпуск от чужого имени. |
| Авторизация | Отзыв refresh-токена проверяется с `await`; access/refresh разделены; одноразовый код потребляется с блокировкой, конкурентное повторное использование запрещено; число попыток ограничено. |
| Защита данных | Старый список сотрудников и статистика не возвращают хеши паролей. Bootstrap администратора не печатает пароль и не создаёт дубликаты. `.env` исключены из Docker-сборок. |

## Проверки

Команда: `npm test` из `back-main/back-main`. Тест сам создаёт и удаляет только свою временную базу.

- Отказ в доступе без входа; права работника, администратора, представителя; изоляция фирм.
- Средневзвешенная цена сырья после прихода.
- Черновик не меняет склад; проведение списывает сырьё, добавляет готовую продукцию и начисляет зарплату.
- Нехватка сырья отменяет всю операцию.
- Одновременное проведение одного выпуска выполняется один раз.
- Изменение рецептуры не меняет ранее проведённую калькуляцию.
- Заявка резервирует товар; одновременные заявки не превышают свободный остаток.
- Отгрузка списывает один раз, сохраняет сумму продажи; отмена освобождает резерв один раз.
- Выплата видна работнику; превышение начисленного остатка отклоняется.
- Новые отчёты, зарплаты, выплаты и продажи соответствуют исходным API.
- Приход из нескольких строк; повторный документ; оплата сразу и позже; откат всех строк при ошибке.
- Прочие расходы доступны в новом интерфейсе.
- Сверка проходит как с новыми операциями, так и с прежней зарплатой и авансами в тестовой базе.
- Одноразовый код не используется дважды при параллельных запросах.
- Выгрузка не содержит паролей и токенов; выход отзывает refresh-сессию.
- Повторный перенос связей с историей не создаёт дубликатов.

## Интерфейс

Проверены формы на обычном экране и во фрейме шириной 390 px. На телефоне видны «Обзор», «Приходы», «Производство», «Заявки» и «Ещё»; длинное горизонтальное меню убрано. Добавлен быстрый «+ Приход» на главной. Поставщик и номер документа необязательны, дата подставляется. Новый материал можно создать внутри прихода. Финансовые подробности и история движений спрятаны в раскрываемых блоках.

Через браузер проведены демонстрационные выпуск 10 кг, заявка и отгрузка 4 кг, приход двух материалов на 700 ₸ с отметкой оплаты. После перезапуска данные сохранились, сверка текущей базы проходит. В этой базе пока только демо-данные.

## Зависимости и оставшиеся ограничения

Зависимости сервера и клиента обновлены; неиспользуемые `crypto` (npm-пакет), `uuid` и `umzug` удалены с сервера. Для Sequelize используется совместимая версия UUID 11.1.x через override. bcrypt обновлён до 6, Nodemailer — до 10, React Router — до 7. На момент этой проверки `npm audit --omit=dev` показывает 0 известных уязвимостей у runtime-зависимостей сервера и клиента. Известные проблемы runtime-зависимостей проверяются командой `npm audit --omit=dev`; результат сохраняется отдельно в `artifacts/dependency-audit.json`.

В инструментах разработки остаются npm-advisory. При обычном запуске используется сервер собранного интерфейса scripts/local-web.js; PHONE.cmd включает доступ по локальной сети. Webpack-dev-server не используется для обычной работы. В облаке нужен собранный фронтенд за HTTPS. Сборка проходит с предупреждениями о размере JS; прежний интерфейс загружается отдельным чанком.

Проведённые документы пока не сторнируются через интерфейс. Корректировка/возвраты, частичная оплата закупки, касса, долги клиентов, реальная 1С и полноценная автономная работа не реализованы. Продажа при отгрузке не означает, что деньги уже получены; экран финансов не называет разницу чистой прибылью или кассовым остатком.
