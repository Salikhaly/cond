# Локальный запуск COND

Из папки проекта в PowerShell:

```powershell
.\start-local.ps1
```

Откройте http://127.0.0.1:9000. Docker не нужен. Скрипт запускает отдельный PostgreSQL на 55432, API на 3000 и React на 9000. Все сервисы слушают только этот компьютер. Вход по email и паролю здесь включён флагом LOCAL_DEMO; в рабочем окружении остаётся вход с кодом из почты.

## Тестовые аккаунты

| Роль | Email | Пароль |
|---|---|---|
| Администратор | admin@local.test | Local2026!demo |
| Работник | worker@local.test | Local2026!demo |
| Представитель | firm@local.test | Local2026!demo |

Кнопки на экране входа заполняют форму. Для входа нажмите «Войти в систему».

Демо-данные: сырьё, упаковка и рецептура на 10 кг сливочного печенья. Перезапуск не пополняет остатки и не сбрасывает документы. Данные PostgreSQL хранятся в `C:\codex-local\cond-postgres`, исполняемые файлы — в `C:\codex-local\cond-postgres-runtime`. Эти пути выбраны из-за ограничений Windows PostgreSQL при работе с кириллическими путями. `.env` и секрет JWT создаются локально и не включены в Git.

## Рабочий процесс

1. Администратор создаёт материалы (кг, л, шт) прямо из прихода и записывает один документ с несколькими строками. Поставщик и номер необязательны; дату система подставляет. Стоимость остатка пересчитывается по средневзвешенной цене. Поступление учитывает склад. Отметка «Уже оплатили» записывает расход; оплату можно внести позже из списка приходов, без повторного изменения склада.
2. В калькуляции выбирает товар, задаёт выход готовой продукции, расход сырья и упаковки, ставку работника за кг и прочие затраты. Рецептура описывает расход на заданный выход, включая потери: 11 кг сырья могут давать 10 кг продукции.
3. Работник записывает фактически изготовленные кг. Администратор может записать выработку за работника. Это черновик: склад и зарплата ещё не меняются.
4. Администратор открывает «Рассчитать и провести», проверяет расчёт и нажимает «Провести с учётом работников». В одной транзакции списываются материалы, добавляются кг готового товара и начисляется зарплата. Сохраняются версия рецептуры, цены и ставка. Повторное проведение запрещено. Нехватка сырья отменяет всю операцию. Проведённый выпуск не редактируется и не отменяется; сторнирование — отдельная будущая операция.
5. Представитель видит свободные кг, собирает заявку, указывает дату и комментарий. Организация берётся из его профиля. Товар резервируется сразу. Администратор видит все заявки, согласует цены за кг и подтверждает отгрузку. Только отгрузка списывает готовый товар и записывает доход. Отмена освобождает резерв. Представитель видит только свои заявки.
6. Накладная доступна в заявке: «Накладная / печать» → «Печать / сохранить PDF». До отгрузки это проект накладной. Это внутренний складской документ; реквизиты и юридический формат настраиваются отдельно.
7. Зарплата показывает проведённую выработку, начисления, выплаты и остаток. Выплата/аванс разрешены в пределах начисленного остатка и отражаются в расходах. Денежная сводка использует общий журнал Salary и учитывает прежние начисления и авансы из этой же базы. Новые выпуски и выплаты отражаются и в предыдущих отчётах и авансах. Килограммы в новом разделе показаны по новому журналу выпуска.

### Согласования и уведомления

- В шапке у администратора есть колокольчик со счётчиком. При новом согласовании он коротко пульсирует, а на главной появляется зелёная плашка «Подтвердить».
- Внутри — короткий список: заявка, зарплата, прошлый выпуск, смена, возврат, выпуск на проверке. Одна строка и одно действие.
- Отдельный раздел «Согласования» доступен из меню «Ещё» и из колокольчика.
- Главная сохраняет блоки действий, метрик, задач, плана выпуска и склада. Вместо дохода и долгов показывается только расход за период: сумма и диаграмма по статьям. Добавлена плашка «Подтвердить».
- Формы приведены к одному виду: крупные поля, короткие подписи, детали скрыты под «Детали», на телефоне одна колонка и кнопки 50 px. Ошибки короткие: «Нет связи», «Не получилось. Повторите».
- Палитра: основные кнопки — чёрные, ссылки и вторичные действия — синие, быстрые действия — зелёный/синий/оранжевый/фиолетовый. Зелёный остаётся для успеха и статусов.
- Разделы меню, метрики и быстрые действия окрашены по смыслу. Главная по умолчанию показывает неделю, чтобы свежие расходы не терялись в начале месяца.
- Начальные остатки по счетам и переводы между счетами убраны из интерфейса. Старые записи сохраняются в базе, но новые не создаются.

### Приход коробками, аналитика, ставка и аванс

- В карточке материала с единицей `шт` можно указать упаковку (например, «коробка») и стандартное число штук в ней. У поставщика есть своё значение по умолчанию: 240, 306 или 360. В конкретном приходе оно подставляется, но его можно изменить.
- В приходе выбирается поставщик из списка; показывается последняя закупка этого материала у него. Поля «Коробок», «Штук в коробке» и «Цена за 1 шт». «Коробок» можно не заполнять — тогда считается одна коробка. Система считает `всего = коробки × штук в коробке` и `сумма = всего × цена за штуку`. Остаток и цена материала хранятся в штуках. Старые приходы без коробок открываются как раньше.
- Если пришло меньше обычного, у строки прихода можно включить «Пришло меньше обычного» и выбрать причину: бой, недовоз, брак, пересорт, повреждение упаковки или «другое» с комментарием.
- «Приходы и склад → Аналитика» показывает за 2 месяца, 3 месяца, год или свой период: коробку (240/306/360 шт), коробки, штуки, среднюю и последнюю цену за единицу, сумму и частую причину недопоставки по каждому поставщику. Вкладки «Сравнение цен» и «По месяцам» сравнивают поставщиков за период и внутри каждого месяца.
- В карточке работника (создание в «Настройки → Пользователи» или «Команда и зарплата → Условия → Карточка сотрудника») можно указать индивидуальную ставку за кг. Она применяется к новым выпускам; прошлые выпуски сохраняют свой расчёт. Персональная ставка за конкретный товар в «Условиях оплаты» важнее.
- В «Расходах» есть «+ Аванс»: работник, сумма, дата и счёт. Аванс уменьшает сумму к выдаче, но в отчёте по работнику показывается отдельно от зарплаты.

Предыдущий интерфейс сохранён по `/legacy` для просмотра истории. Запись через старые API отключена, чтобы обход новых операций не рассогласовал сырьё, резерв, склад и зарплаты. Новые операции проводятся в основном рабочем месте. Перед подключением существующей рабочей базы нужны резервная копия и отдельный перенос начальных остатков, рецептур и долгов по зарплате.

## 1С

Раздел «Доступ и 1С» выгружает JSON `cond.exchange.v1` со стабильными идентификаторами: материалы, приходы, рецептуры, остатки, выпуск с калькуляциями, заявки и выплаты. Выгрузка не содержит паролей и токенов. Это контракт данных для будущего адаптера, **не готовая синхронизация с 1С**. Для прямого обмена нужны название и версия конфигурации 1С, тестовая база, соответствия справочников, документов и единиц, правила повторной доставки и согласование направления обмена.

## Проверка

```powershell
cd back-main\back-main
npm test
```

Тест создаёт отдельную временную PostgreSQL-базу, запускает API на 3001, проверяет транзакции, калькуляцию, зарплаты, роли, изоляцию организаций, одновременное проведение и резервирование, отгрузки, отмену и отзыв refresh-токена. По завершении удаляет только свою тестовую базу.

```powershell
cd front-main\front-main
npm run build
```

После первого входа доступны сохранённые данные, предварительная калькуляция и очередь операций без сервера. Записи сохраняются на устройстве и подтверждаются сервером после связи. Установка и повторное открытие PWA на телефоне без связи требуют HTTPS. См. PHONE-AND-CLOUD.md.


Результаты расширенной проверки: [AUDIT.md](AUDIT.md). Варианты доступа с телефона: [PHONE-AND-CLOUD.md](PHONE-AND-CLOUD.md).


Запуск двойным щелчком: START.cmd. Доступ для телефона в той же Wi-Fi сети: PHONE.cmd. Сервер раздаёт собранное приложение; webpack-dev-server больше не нужен при обычном запуске. После изменения исходников пересобрать front-main/front-main командой npm run build.

Офлайн-работа телефона без Wi-Fi и сервера, очередь отправки, установка PWA и ограничения описаны в PHONE-AND-CLOUD.md. Для установки и повторного открытия на телефоне без связи требуется доверенный HTTPS. Сейчас внешний сервер не подключён.
