## Как устроено

- Статические файлы React и фотографии обслуживает Vercel CDN.
- `/api/*` обрабатывается Vercel Function, использующей существующие бизнес-сервисы Express/Sequelize.
- `src/publicDemo.js` — отдельная точка входа. Проверяет явные demo-флаги, отдельную базу Neon, HTTPS и отдельный ключ подписи; не подключается к локальной синхронизации.
- Первичное наполнение защищено блокировкой PostgreSQL. Таблицы и демонстрационные операции создаются один раз. Все операции наполнения и маркер готовности записываются одной транзакцией через существующий механизм идемпотентности. Новые экземпляры функции и повторные релизы не сбрасывают изменения пользователей.
- Начальные данные: два товара с изображениями, два сотрудника, три магазина (включая сеть), пять отгрузок за неделю, две новые заявки, одна согласованная, выпуск на проверке, зарплаты и расходы. Первоначальные записи датированы 21–27.10.2026; отчёты используют текущую дату Казахстана, включая новые возвраты.
- Пароли хранятся как bcrypt-хеши. Refresh-cookie: HttpOnly, Secure, SameSite=Lax. Права проверяются сервером.
- Общие demo-аккаунты нельзя заблокировать через настройки доступа. Почтовый вход и приём синхронизации выключены в публичном demo-handler; обычный refresh/logout работают.
- Переменные подключения к БД и ключ подписи находятся в Vercel Environment Variables, отсутствуют в сборке браузера и в пакете релиза.
- Реальный production-режим в `config/validate.js` по-прежнему запрещает LOCAL_DEMO. Публичное демо использует отдельную точку входа, а не ослабление production-проверок.

## Сборка и повторная публикация

1. В отдельном PowerShell-процессе, в `front-main/front-main`: задать PUBLIC_DEMO=true, LOCAL_DEMO=true, затем выполнить `npx webpack --mode production --output-path ../../artifacts/public-demo-build`.
2. Из корня: `node deploy/vercel-demo/prepare.cjs`. Получится отдельный каталог релиза в artifacts и manifest `artifacts/cond-demo-files.json`. Приватные env/БД/логи не включаются.
3. Публиковать только этот подготовленный каталог в существующий проект `cond-demo`, команда `sakes-projects-48a0734d`. Не публиковать весь рабочий каталог.
4. Настройки: Node 24, Framework Other, Output public, Build command пустой, Install `npm install --omit=dev --no-audit --no-fund`. Конфигурация функций и маршрутов создаётся prepare-скриптом.
5. Проверить `/api/health`, три роли и `/operations/reconciliation` с авторизацией администратора. `node artifacts/check-public-release.cjs` выполняет основные HTTPS-проверки.

Vercel CLI в текущей среде имел недействительную авторизацию; публикация выполнена через подключённый Vercel API. При использовании CLI требуется свой обычный `vercel login`, токены не записывать в проект.
