# COND — выполнение мобильного UI/UX-плана

Дата начала: 05.11.2026. Задача пользователя: **«по плану сделай все»**. Работа продолжается; этот файл не является актом завершения.

## Зафиксированные решения
- Главная владельца: действия и контроль. Быстрые действия: расход, приход сырья, аванс, оплата клиента.
- Обычная операция сохраняется одной кнопкой; превышение аванса, отмена и исправление требуют явного подтверждения.
- Коробки и размер фасовки — основные единицы; рядом общий вес. Нельзя заменять неизвестные суммы нулями.
- Магазин получает персональную ссылку без регистрации, видит свои цены и статус наличия, без точного склада и долгов.
- Заказ по ссылке относится к закреплённому представителю, по прежним правилам оплаты. Отправка не резервирует товар и не начисляет зарплату.
- Сохранить действующие документы, учёт, права, согласование актов и условий оплаты. Реальные данные не заменять тестовыми.
- Локальные финансовые проверки — только в автоматически удаляемых именованных тестовых базах, Telegram выключен. После приёмки обновить существующий Vercel-проект cond-demo.

## Реализовано локально
- Нижнее меню владельца: Главная / Заявки / Производство / Деньги / Ещё; пункт Деньги в основном меню — владельцу.
- Главная: поиск объектов, четыре быстрых действия, задачи максимум по три, прямые переходы к товару/материалу, компактная ссылка на результаты. Убрана повторяющаяся полоса согласований.
- Поиск: товары, сотрудники, магазины, заявки и приходы, с идентификатором конкретной записи. Нормализация е/ё для поиска товара.
- Одно сохранение расхода, аванса и клиентской оплаты; подтверждённый результат, переход к записи и повторный ввод.
- Общий useRecordedAction сохраняет номер до отправки, повторяет тот же запрос и восстанавливает результат после отправки очереди. Отклонённая запись остаётся в очереди до исправления/удаления.
- Аванс: нет автоматического первого сотрудника, выбор по имени, запуск из зарплаты конкретного сотрудника; API больше не разрешает превышение неявно. Для администратора необходимы payroll и cash.
- Быстрые статьи: до шести вариантов, непонятные импортные заголовки не выводятся в быстрых плитках; история не переименована. Светлые плитки в две колонки.
- Карточка товара открывается из поиска/остатков. Отдельное редактирование фото, управление публикацией, группой, описанием и порядком витрины.
- Фото: камера/галерея, квадратный кадр, поворот, JPEG до 400 КБ и миниатюра до 60 КБ. HEIC-модуль загружается по требованию. Исходный снимок до подготовки и выбранный кадр после подготовки сохраняются в IndexedDB пользователя. Версия предотвращает перезапись с другого устройства.
- Общий dashboard не содержит base64 фото; картинки выдаются отдельно и миниатюры кэшируются по пользователю/версии. Старые фото сохраняются.
- Исправлена старая ошибка: обычное редактирование товара больше не меняет вместимость первой коробки. Явная смена ставки неиспользованного товара обновляет оплату коробок без изменения размера.
- Отдельная гостевая витрина, общий расчёт индивидуальных цен с основным оформлением заказов, группы, поиск, 24 товара на страницу, корзина и заявка.
- Ссылка магазина: только владелец может создать/отозвать/перевыпустить. На сервере только хеш; повтор выдачи воспроизводит тот же секрет через HMAC и номер операции, без сохранения секрета в журнале или квитанции идемпотентности.
- Гостевой API выдаёт только разрешённые поля, не использует /dashboard. Ограничения частоты в PostgreSQL, привязка магазина на сервере, уникальный источник заказа, защита повторов и изменения цены во время оформления.
- Отдельная загрузка интерфейсов владельца и магазина. Гость не запускает рабочее место владельца и не регистрирует его офлайн-оболочку. HEIC исключён из предварительной загрузки, после первого использования модуль доступен офлайн.

## Сверка, бонусы товаром и результат — 05.11.2026

Последнее решение владельца заменяет прежний план денежных счетов: в интерфейсе только способы оплаты Наличные / Карта–Kaspi / Банк, без переводов, управления счетами и требования вводить остаток. Исторические денежные документы не удаляются; переводы/начальные остатки/сверочные корректировки не входят в новый отчёт оплат. Изменение денег за период не называется прибылью или банковским остатком.

- Владелец видит вкладки Оплаты / Результат бизнеса. Четыре показателя результата раскрываются в записи с переходом в исходный документ и возвратом в тот же период. Чужие права и контакты сохраняют прежнюю серверную защиту.
- Акт сверки поставщика учитывает документы и оплаты до начала периода, старый basePaid один раз, оригинал отменённого платежа и его обратную запись по их датам. Отрицательное сальдо остаётся авансом. В телефоне — карточки с текущим долгом, на компьютере и печати — акт; Excel включает выбранный период. Начало месяца берётся из бизнес-даты без смещения на предыдущий день UTC.
- Новый бонус — фактически выданные коробки к проведённой поставке. ClientBonus.goods хранит источник, отдельную нулевую отгрузку и снимок стоимости. Склад/резерв/стоимость/связь создаются атомарно. Долг и повторная оплата труда не меняются. Старые денежные бонусы остаются историей, новые денежные начисления отключены.
- Запрос бонуса требует устойчивый номер операции. Повтор не создаёт вторую отгрузку; нехватка товара откатывает всё. Представителю и работнику проведение запрещено. Для администратора проверяется разрешение на заявки. Бонус проводится онлайн, несохранённое подтверждение остаётся на телефоне для безопасного повтора.
