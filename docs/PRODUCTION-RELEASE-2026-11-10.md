# COND — расходы, приходы и витрина

Обновление основано на рабочем production-коммите e73e018. Локальные Excel-импорты и отчёты из ветки monthly-excel-local в релиз не входят.

## Изменения

- Справочник: SVG парковки, бензоколонки, тарелки и кофе; недостающие статьи добавляются без повторов. Встроенный «Бензин» получает соответствующую иконку.
- Упаковка: плёнка доступна даже при пустом справочнике; материал выбирается со склада, норма — метры на коробку. Используется существующий расчёт и списание. Покупку через приход не нужно дублировать расходом; старые самостоятельные расходы не преобразуются в приходы.
- Приход: исправление, частичный возврат и отмена из одной карточки. Исходник сохраняется. При отмене эффективные строки пустые, сумма нулевая; история и расчёт последствий сохраняются существующим механизмом корректировок. Возврат денег поставщиком создаёт отдельное связанное денежное движение; альтернативно оплата остаётся авансом. Возврат денег ограничен свободным авансом после изменения, в том числе с учётом других приходов.
- Проведённый выпуск можно отменить администратору, если товар не использован и после него нет движений готовой продукции. В одной транзакции возвращаются материалы/коробки/плёнка, снимаются товар и начисление, пересчитывается дневная зарплата. Старый акт и снимок расчёта сохраняются. При последующих движениях требуется сначала урегулировать их.
- Ассортимент: клиентский набор товаров и конкретных packId; магазин наследует его либо использует собственный набор. До настройки прежняя видимость сохраняется; явно пустой набор скрывает всё. Новые фасовки не появляются в сохранённом наборе автоматически. Общая публикация обязательна. Проверки применяются к представителю, публичному каталогу, фото и отправке заявки.
- Главная, заказ представителя и витрина группируют названия с весом в один визуальный товар. Идентификаторы и цены исходных фасовок сохраняются; это не автоматическое объединение бухгалтерских карточек.
- Владелец видит предполагаемые дубли, выбирает основной товар и подтверждает архив дубля. Блокируются любые ненулевые остатки, резервы коробок/кг, открытые заявки, выпуски и незавершённые возвраты. Документы и рецепты сохраняются.
- Компактные отступы, крупные телефонные шрифты сохранены.

## Интерфейсы и совместимость

GET/PUT `/api/operations/assortment/:type/:id`, type = customer/outlet; владелец. PUT: version, override (для магазина), items[{productId,packIds,loose?}]. Правила версионируются в существующей таблице LegacyLink. Новых таблиц и разрушительной миграции нет.

GET `/api/operations/outlets/:id/order-catalog` возвращает разрешённый каталог закреплённого магазина. GET `/api/operations/products/duplicates` и POST `/api/operations/products/:id/archive-duplicate` доступны владельцу.

Существующий API корректировок принимает action edit/return/cancel, returns[{materialId,quantity}], settlement advance/refund, refundAmount, method. Предпросмотр возвращает доступный возврат и изменения; подтверждение требует fingerprint, версии и operation ID. Старый формат исправления остаётся рабочим.

Денежный приход от поставщика имеет kind=supplier-refund. Он уменьшает чистую оплату по связанному приходу и показывается в денежном отчёте и сверке. Старые ссылки магазина остаются действительными.

## Проверки

Изолированные БД: 23 сценария прежних корректировок, 15 сценариев плёнки, 35 сценариев публичной витрины, 18 новых сценариев ассортимента/возврата денег/отмены/дублей. Фронтенд: расчёт полной себестоимости, группировка без изменения ID и проверка порядка hooks. Сборка проходит с прежним предупреждением о размере ресурсов.

С рабочего API снята локальная копия актуального каталога: 54 карточки и 13 предполагаемых групп дублей. Копия используется только для просмотра, реальные карточки автоматически не архивируются. Снимки и локальные журналы находятся в игнорируемом deploy/backups и не публикуются. Прямой SQL-доступ не использован: значения подключения через Vercel скрыты.

На 390 px проверены вход, главная без повторения «Арахисовой», выбор отдельной коробки, сохранение и повторное открытие ассортимента. Горизонтальная прокрутка отсутствует. Новые статьи появятся при штатном запуске существующей аддитивной процедуры обновления.

Откат к прежнему deployment не удаляет сохранённые операции/ассортимент. После появления supplier-refund старый код не умеет правильно сворачивать такой платёж: для отката учёта нужен совместимый исправленный релиз, а не возврат старой версии расчёта.
