# Торговый представитель: магазины, каталог и заявки

Рабочий процесс
1. Администратор создаёт доступ торговому представителю в настройках.
2. В разделе «Магазины» добавляет клиента и одну или несколько торговых точек с адресами; закрепляет за представителем.
3. Представитель видит только закреплённые магазины. Открывает магазин → «Собрать заказ» или выбирает его в каталоге.
4. В каталоге видны фото, описание, вес коробки и свободные кг. Количество вводится коробками или кг. Заказ сверх наличия принимается под производство.
5. «Проверить заказ» показывает магазин, адрес, товары, кг, дату и комментарий. Только следующая кнопка отправляет заявку.
   Выбранный магазин свёрнут в компактную карточку с кнопкой «Изменить». Корзина появляется после добавления товара; пояснение про цены раскрывается по нажатию.
6. Администратор проверяет новую заявку, вводит цены и подтверждает резерв. При нехватке показан недостающий выпуск; сервер также запрещает согласование без товара.
7. После подтверждённого производства заявку можно согласовать. Подтверждение отгрузки списывает готовую продукцию и создаёт продажу в прежнем журнале.
8. Накладная сохраняет фирму, магазин и адрес на момент создания заявки. Переназначение представителя не меняет старые документы.

Каталог
«Товары и фото» → «Фото и описание». Поддержаны JPG, PNG и WebP. Интерфейс уменьшает фото до 900 px и размера, подходящего для телефона. Сервер принимает до 400 КБ и проверяет тип. Фото может менять только администратор. Новые фото передаются с каталогом и сохраняются вместе с данными на телефоне. Если реального фото нет, это явно указано; иллюстрации не выдаются за реальные снимки продукции.
Создание готового товара перенесено из калькуляции в каталог. Рецептура и ставка редактируются в «Калькуляция».

Клиенты
Несколько магазинов могут принадлежать одной фирме. Для независимого магазина создаётся отдельный клиент. Поле «Общий счёт / по магазинам» задаёт структуру будущего учёта; полноценные оплаты покупателей и долги этим не реализованы. Представитель пока собирает заказы: не назначает цены, не отгружает и не записывает получение денег.

Без связи
Корзина сохраняется на устройстве отдельно для аккаунта. Отправленная без связи заявка хранится в очереди и видна в истории с отметкой «На телефоне». Подтверждённой считается после ответа сервера. Сервер повторно проверяет закрепление магазина. При переназначении магазина офлайн-заявка может быть отклонена и остаётся в очереди для исправления.
Физические Android/iPhone требуют отдельной приёмки по HTTPS.

Совместимость
Добавлены таблицы клиентов, магазинов, адресов заявок и представления товара; существующие продажи и зарплаты не удаляются.
Однократная миграция переводит резервы на согласованные заявки. Сохраняются approved-резервы, освобождаются резервы submitted-заявок. Повторный запуск не повторяет миграцию. Перед обновлением в .local-logs/backups сохранены JSON-снимки остатков/заявок; это ограниченный снимок перехода, не полноценная проверенная резервная копия всей системы.
Старые заявки без магазина доступны как история. Профиль старой фирмы оставлен для совместимости прежних клиентов API; новый интерфейс требует выбора магазина для торгового представителя.
Внешняя копия и JSON для будущей 1С включают новые сущности. Доступ к магазинам в копии ограничивается представителем исходной базы.
Файлы приложения теперь имеют хеш версии: обновление не подставляет старый bundle.js из кеша. Сохраняется предыдущий кеш для уже открытых вкладок.

Проверки
71 интеграционная проверка учёта/доступа/фото/магазинов/миграции прошла в изолированной базе. В том числе проверено, что продажа сохраняет конкретный магазин и клиента, а cookies входа разделены между локальными базами. 12 проверок синхронизации, 49 проверок аналитики, 7 конфигурации и 7 запуска production API прошли.
В отдельной одноразовой базе проверено: API и сайт остановлены → заявка сохранена → повторное открытие без сервера → восстановление связи → ровно одна заявка на 2 кг с исходным адресом, без резерва до согласования. База и процессы проверки удалены после теста.
В живой демо-базе проверены карточки трёх магазинов, сбор 2 коробок = 4 кг, проверка заказа и просмотр карточки товара. Проверочный приход доведён до подтверждения, но не записан.

Запуск
START.cmd — основной локальный вариант.
PRESENTATION.cmd — отдельная демо-база, три магазина двух клиентов. Существующие записи и ваши пробы не сбрасываются.
Для внешнего запуска всё ещё требуются сервер, домен, HTTPS, SMTP, проверка восстановления копии и приёмка устройств. Прямой адаптер 1С и полный учёт долгов не подключены.
